# JARVIS PRO — Automation + Remote Control + Live Conversation

IMPORTANT:
- Do NOT replace your JARVIS PRO ZIP.
- Do NOT copy Mark's main.py.
- Do NOT remove the existing NCI/voice system.
- Add these files to the original JARVIS PRO source.

## 1. Add the files

Copy:

skills/automation/home_automation.py
    -> JARVIS-PRO/skills/automation/home_automation.py

services/remote_control.py
    -> JARVIS-PRO/services/remote_control.py

voice/live_conversation.py
    -> JARVIS-PRO/voice/live_conversation.py

Create empty __init__.py files if these folders do not already have them:
    JARVIS-PRO/skills/automation/__init__.py
    JARVIS-PRO/services/__init__.py

## 2. Load the automation skill

Open:
    JARVIS-PRO/skills/loader.py

Add this line inside SKILLS:

    "automation.home_automation",

Do not remove any existing skill.

## 3. Start the remote-control server

Open:
    JARVIS-PRO/core/services.py

Add:

    from services.remote_control import RemoteControlServer

    remote_server = None

    def start_remote_control(command_handler):
        global remote_server

        remote_server = RemoteControlServer(
            command_handler=command_handler
        )

        if remote_server.start():
            print(
                "[REMOTE] Open:",
                remote_server.url()
            )

        return remote_server

Do not remove the existing start_all() behavior.

## 4. Connect the remote server to the existing dispatcher

In the module that starts your normal dispatcher/runtime, use:

    from services.remote_control import RemoteControlServer
    from core.dispatcher import dispatch

    remote_server = RemoteControlServer(
        command_handler=dispatch
    )
    remote_server.start()

Do NOT create a second brain/router.

The phone sends normal JARVIS text commands into:
    dispatch(...)
which keeps your existing intelligence architecture.

## 5. Start Live Conversation

The cleanest approach is to register the live-mode actions from your existing
skill-loading path.

Add this import once during online startup:

    from voice.live_conversation import (
        start_live_conversation,
        stop_live_conversation,
        live_conversation_status,
    )

Then register them with the existing registry:

    from core.registry import register

    register(
        "start_live_conversation",
        start_live_conversation,
        category="voice",
    )

    register(
        "stop_live_conversation",
        stop_live_conversation,
        category="voice",
    )

    register(
        "live_conversation_status",
        live_conversation_status,
        category="voice",
    )

Your existing intent/dispatcher can then invoke them.

If your dispatcher has explicit command aliases, add:

    "start live conversation"
        -> start_live_conversation

    "stop live conversation"
        -> stop_live_conversation

    "live conversation status"
        -> live_conversation_status

## 6. API key

Preferred:

Windows PowerShell:

    $env:GEMINI_API_KEY="YOUR_KEY"

Or permanently:

    setx GEMINI_API_KEY "YOUR_KEY"

The live module also checks:
    config/api_keys.json
for:
    "gemini_api_key"

Do not hard-code the key into Python source.

## 7. Install only the new dependencies

    pip install google-genai sounddevice numpy fastapi uvicorn

You may already have some of these.

## 8. ESP32

Set:

    $env:JARVIS_ESP32_IP="192.168.x.x"

Replace the address with your actual ESP32 address.

Then:

    "turn on the light"
    "turn off the fan"
    "what is the automation status"

## 9. Remote control

Start JARVIS.

The remote service prints something like:

    [REMOTE] Server: http://192.168.1.10:8765

Open that address from your phone while both devices are on the same Wi-Fi.

A pairing PIN is generated by calling:

    remote_server.new_pairing_pin()

The PIN expires after 10 minutes.

## 10. Live conversation

After registering the three actions:

    "Start live conversation."

JARVIS enters Gemini Native Audio mode.

You can talk continuously without saying the wake word for every sentence.

Say:

    "Stop live conversation."

to return to the normal JARVIS voice system.

## IMPORTANT LIMITATION

This Live Conversation module intentionally does not replace your existing
NCI/dispatcher/voice pipeline.

It is an optional Native Audio voice mode.

Mark's original remote phone microphone implementation is tightly coupled to
Mark's large JarvisLive class and dashboard. Do not paste Mark's main.py into
JARVIS PRO. First get local Live Conversation working; then the phone microphone
can be bridged into the same live audio queue safely.
